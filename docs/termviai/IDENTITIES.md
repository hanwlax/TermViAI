# Keychain Identities and Host authentication

Keychain keeps separate Keys and Identities sections with the existing card layout, muted purple surfaces and right-side editor. Keys reference local private-key files. Click either a Key or Identity card to edit it; both editors provide a two-click Delete action above the footer separator. Keys allow editing the name and path. Deleting a Key only removes its library entry, never its private-key file, and is blocked while a saved Host references it. An Identity has a label, username and password. Click its card to edit; leaving the password empty retains the stored password. Deleting an identity requires a second click and is blocked while a saved Host references it.

The Host drawer has three mutually exclusive Authentication segments:

- **Password** (default): username and password. Saving the Host saves the password to Windows Credential Manager. There is no Remember checkbox.
- **SSH Key**: username plus either a manually entered private-key file path or a selected Keychain key. File path and Keychain are mutually exclusive sources within this mode.
- **Identity**: choose an existing Keychain Identity. Its username and eight password bullets appear in a read-only summary; manual username, password and key fields are hidden.

Address and Port share a row. Group follows Authentication. Save and Cancel have the same neutral background at rest; Save turns muted purple on hover. The drawer uses the existing native palette, vectors, rounded inputs and slide animation. Key and Identity dropdowns scroll when needed. Arrow keys change the open list selection; Enter, Tab or Escape dismiss the list without submitting or closing the Host editor. Empty lists and missing references have explicit messages.

Switching modes or key sources preserves draft values only while the form is open. Save persists only the active mode and source; inactive passwords are not written to the credential vault. Saved workspaces and recent connections retain the selected mode and Keychain references, resolving current values only when connecting. Keys use their unique label; Identities use an opaque ID. Key renames update saved Host references and retain previous labels as aliases for workspace/recent snapshots and other windows. Previous names stay reserved to the same Key, preventing old references from resolving to a different key. Editing or deleting a stale Key snapshot is rejected. Existing Hosts without an authentication discriminator retain legacy SSH behavior until edited. The editor infers Identity first, then Key if a key is configured, otherwise Password; saving explicitly adopts that mode.

An unchanged stored password displays exactly eight solid bullets (`••••••••`), never loaded into the edit buffer. Leaving it untouched/empty preserves it; entering text replaces it. Show/Hide applies only to newly typed text. Hidden passwords are excluded from copy/cut.

Passwords are stored using the current Windows user's Credential Manager under `TermViAI/password/<opaque id>`. Host JSON, workspace JSON, SSH configuration maps and domain names contain only opaque references, never password values. Legacy beta.4 temporary passwords migrate to persistent storage on Password-mode save if still available; expired temporary passwords require re-entry. Old identity-owned references are not mistaken for Host-owned passwords or deleted when switching modes. Replaced Host passwords are removed when no saved Host owns the reference. Other platforms reject persistent password storage instead of using plaintext.

The library is re-read and stale edits are rejected before credential updates. A metadata write failure attempts to roll back the credential. Missing Identity or Key references report an actionable error. Identity password changes retain the same reference, so a new authentication attempt reads the new password. Already authenticated SSH sessions remain connected.

Explicit Password and Identity modes skip public-key and agent authentication in both SSH backends. Explicit Key mode uses only the chosen private-key file (including paths with spaces), prompting for its passphrase if necessary. It does not load a saved Host password or try other agent/default keys. After a key completes the first authentication factor, additional server challenges remain interactive. Legacy callers without an explicit mode retain their existing behavior.

Both libssh and ssh2 try a supplied password at most once per authentication flow, after host verification. If rejected, interactive password authentication remains available. A keyboard-interactive challenge is auto-answered only when it consists of exactly one non-echo prompt named `Password` or `Password:` (case-insensitive). OTPs, new-password challenges and private-key passphrases remain interactive. No password is added to command-line arguments or SSH option values.

Tests cover Windows credential round-trip/replacement/deletion, temporary-password migration/expiry, safe challenge classification, legacy loading, mode-specific resolution and saving, draft preservation, cached-session separation, unchanged passwords, Unicode masking and drawer/dropdown bounds. Test credentials are synthetic and use isolated IDs; no real Host or credential is modified. Real SSH authentication and native mouse/visual behavior still require manual acceptance on the target machine.

Deleting a Host removes its Hosts library entry after confirmation. It does not close live sessions or remove Keychain entries, saved workspaces or recent connections. Credential references remain available to these consumers, including duplicated Hosts. The library is reloaded and the captured Host must still match before deletion is saved.

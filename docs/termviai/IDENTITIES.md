# Keychain Identities and Host authentication

Keychain keeps separate Keys and Identities sections with the existing card layout, muted purple surfaces and right-side editor. Keys remain references to local private-key files. An Identity has a label, username and password. Click its card to edit; leaving the password empty retains the stored password. Deleting an identity requires a second click and is blocked while a saved Host references it.

Host editors accept a password, show/hide it explicitly, and offer Remember password. The Authentication button opens a scrollable Keychain picker for a private key or Identity, or returns to manual credentials. Linked identity fields are read-only and display their source. A selected key populates the private-key path. Hidden password text is excluded from copy/cut and is shaped only as bullets; selection/caret offsets use the displayed glyphs.

Passwords are stored using the current Windows user's Credential Manager under `TermViAI/password/<opaque id>`. Host JSON, workspace JSON, SSH configuration maps and domain names contain only opaque references, never password values. Unchecked Remember password uses an in-process map; the persisted reference cannot recover its password after the application exits. Checking/unchecking Remember can move an existing password between these stores without retyping it. Replaced credentials are removed when no saved Host owns that reference. Explicitly remembered passwords are supported on Windows; other platforms reject persistence rather than writing plaintext.

The library is re-read and stale edits are rejected before credential updates. A metadata write failure attempts to roll back the credential. Existing libraries load with empty identity/reference fields. Identity references are resolved before creating a new SSH workspace; missing identities report an actionable error. Identity password changes retain the same reference, so a new authentication attempt reads the new password. Already authenticated SSH sessions remain connected.

Both libssh and ssh2 try a supplied password at most once per authentication flow, after host verification. If rejected, normal interactive authentication remains available. A keyboard-interactive challenge is auto-answered only when it consists of exactly one non-echo prompt named `Password` or `Password:` (case-insensitive). OTPs, new-password challenges, private-key passphrases and other prompts remain interactive. No password is added to command-line arguments or SSH option values.

Tests cover Windows credential round-trip/replacement/deletion, session-only storage, safe challenge classification, old-library loading, identity references, Unicode masking, unchanged identity password, and Remember transitions without retyping. Test credentials are synthetic and use isolated IDs; no real Host or credential is modified. Real SSH authentication and native mouse/visual behavior require manual acceptance on the target machine.

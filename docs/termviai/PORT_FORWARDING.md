# Port Forwarding

本地试用功能，2026-10-29。按已审核的多列紧凑卡片与右侧抽屉设计实现。

## 使用

1. 在 Hosts 中保存需要接收本机服务的 SSH 主机，无需打开对应终端。
2. 从侧栏 **Port Forwarding → Add forwarding** 选择主机，列表支持按名称、地址、用户名和分组搜索；已打开终端也可通过 `⋯ → Add port forwarding` 快速创建。
3. 设置名称、远端监听范围/端口、本机端口。默认远端 `127.0.0.1:18080` 转发至此电脑 `127.0.0.1:8787`。
4. Save 默认中性底色，悬浮使用当前主题强调色。默认保存后启动。应用重启时自动恢复上次应运行的规则，手动停止的规则保持停止。

这是 **SSH 反向 TCP 转发**：远端访问监听端口，流量经 SSH 到运行 TermViAI 的电脑上的服务。不是本地 `-L` 转发、SOCKS 或 HTTP 代理；不提供 REST 接口，不读取 `.ssh/config`，不导入其别名或 ProxyCommand。

来源包括所有已保存的 SSH 主机，并补充当前窗口已打开且未离线的临时 SSH 主机；相同主机来源去重。创建时保存主机地址、端口和认证引用，关闭来源终端或关闭 Port Forwarding 页面不会停止转发。每条规则使用独立 SSH 连接，停止规则不影响交互终端。退出应用会断开所有转发，但不清除运行意图；下次启动无需先打开 SSH 终端，即会用已保存的主机与认证恢复。

## 界面与状态

- Port Forwarding 与 Hosts、Keychain 一样通过侧栏导航，不创建额外顶栏标签。主机选择沿用 Monitor 的分组列表和搜索样式，单击主机进入创建表单；选择抽屉最大宽 560 px。
- 服务卡片按可用宽度自动多列排列，最小列宽 236 px、间隔 10 px、基础卡片高 156 px。典型窗口是 3/2/1 列，大窗口可展示更多列。
- 标题长文本截断，悬浮显示完整服务名；更多菜单保持在窗口内，图标悬浮保留整卡高亮。
- 创建/编辑/详情抽屉宽 438 px，正文独立滚动，标题和操作区固定；键盘 Tab 会滚动到被聚焦的表单字段。继承三套主题和原生 UI 字体。
- 单条启动、停止、编辑、删除；批量启动/停止。停止、删除会中断该转发的 TCP 连接。
- `Tunnel established` 只表示服务器接受 SSH 监听请求，不代表业务健康或网络端口可达。详情的 `Check local service` 单独进行本机 TCP 探测。
- `Remote network` 请求 `0.0.0.0`。实际监听范围受远端 `GatewayPorts` 策略影响，外部可达性还取决于防火墙/路由；服务器可能把监听限制为 loopback。默认使用远端 localhost。
- 自动重试最多 6 次，间隔 1、2、4、8、16、30 秒；用户停止/删除/保存新设置会取消旧任务。认证需交互、已知认证拒绝或监听被拒绝会进入 Needs attention。

## 认证与存储

复用 Host/Keychain 认证定义：已保存密码、Identity、指定 SSH key 或既有 SSH agent。JSON 中只保存不透明凭据引用，密码继续由既有凭据管理器持有。尚未保存的交互密码、未解锁的加密私钥、OTP/MFA 无法在后台自动应答；页面提示先处理认证。端口转发不会自动信任新主机密钥，先在终端验证主机。

规则和运行意图 `desired` 以原子替换保存到 TermViAI 数据目录的 `forwarding.json`。启动/停止先保存意图，状态报错不把运行意图改为停止。启动时校验端口、名称、规则 ID 和同一服务器/SSH 端口上的监听冲突，损坏文件保留且阻止覆写。规则独立保存主机快照；之后修改 Host 地址不会静默改变既有规则，Keychain 引用在启动时解析。

## 端口冲突

SSH 服务器拒绝监听也可能是转发策略禁止，不能直接断定端口冲突。停止状态的详情页可 `Inspect remote listener`；使用独立管理连接执行一次性 Python/`ss` 检查，不运行 NPU 采集。

只有唯一、可读取身份、可控制的非交互 `sshd` / `sshd-session` 会话才显示结束选项。必须再次确认；执行时重新核对 PID 启动身份、可执行程序和监听归属，以 pidfd 定位进程后发送一次 SIGTERM，并等待端口释放才重建转发。未知、多归属、业务进程、交互终端、缺少权限或不具备 pidfd 能力时不提供强制结束。取消检查不能撤销已经发出的信号，结果不确定时需重新检查。

当前不会凭 PID、用户名、主机标签或端口猜测“本应用遗留会话”，也不会自动结束归属记录不匹配的 SSH 会话。确认文案说明该会话可能属于其他应用，其中其他隧道或命令也可能受到影响。冲突检查需要远端 Linux、Python 3、`ss` 及相应权限；普通 TCP 转发本身不需要 Python。

## 重启与意外断连自动恢复（2026-10-29 更新）

建立远端监听之前，应用先在**同一条专用 SSH 连接**上取得所属 sshd 会话的 PID、远端 boot ID 和进程启动时间，并原子保存到 `forwarding-owners/<rule-id>.json`。记录关联服务器地址、SSH 端口、远端监听端口与绑定范围。登记和落盘先于监听请求，应用即使在收到监听 ACK 前崩溃，已有记录也不会丢失该监听的归属。

恢复时先用独立管理连接检查旧端口：端口已释放则直接建立新转发；唯一监听者的 PID/boot ID/启动时间与记录全部相符时，通过 pidfd 再核对身份和端口归属，结束这条旧专用 SSH 会话，等待端口释放后重建。其他程序或其他 SSH 会话占用、PID 复用、远端重启、归属不明或权限不足时不自动结束进程。连接失败继续使用有限重试；认证和归属校验失败显示具体原因。

`forwarding.lock` 使用操作系统文件锁，覆盖同一数据目录的整个转发管理生命周期。另一个仍在运行的 TermViAI 实例持锁时，新实例不会接管或重写规则；崩溃后操作系统释放锁。这避免误把另一个本机活跃实例当作遗留连接。

自动清理依赖远端 Linux `/proc`、Python 3、`ss`、pidfd 与相应权限。首次登记不受支持时仍可在新 SSH 传输上运行普通转发，并显示自动清理不可用的原因；没有归属记录时绝不会凭端口强制清理。已知归属的恢复检查不通过时停止自动清理。

**旧版兼容：**之前的试用版没有保存运行意图和远端归属，不能追溯证明旧会话属于 TermViAI。旧规则仍可读取，缺失的 `desired` 默认 false；首次启动后开始记录，旧无记录占用需一次人工确认。手动停止和删除的规则不会在启动时复活。自动恢复限于同一本机数据目录，不以复制数据目录作为跨设备接管机制。

## 实现与验证边界

- `wezterm-gui/src/forwarding.rs`：持久化、任务状态、重试、探测与管理连接。
- `wezterm-gui/src/termwindow/termviai_forwarding.rs`：原生页面、抽屉、卡片和交互。
- `wezterm-gui/src/forward_control.py`：Linux 监听检查与确认后会话结束。
- `wezterm-ssh/src/forward.rs`：专用 SSH 反向传输，有界双向缓冲、半关闭、并发连接，最多 64 条活动/待连接 TCP 流。

每条隧道使用一个长连接承载业务 TCP 通道，15 秒 SSH keepalive；本机探测不新建 SSH，手动冲突检查使用临时独立 SSH 管理连接。keepalive 不等于可证明的黑洞网络检测时限。

Windows 原生 libssh + 一次性本地 OpenSSH 实测覆盖 3 路并发、180000 字节请求与 210000 字节响应、请求半关闭、端口冲突拒绝、停止后释放监听及独立终端连接保持。冲突保护分支使用 mock 测试，另在一次性本地 OpenSSH 上验证只结束该测试转发会话并释放端口；未连接或结束用户服务器进程。窗口几何测试不能替代不同 DPI/GPU、真实网络/服务器策略下的人工试用。

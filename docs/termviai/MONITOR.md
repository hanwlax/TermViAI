# NPU Monitor（试用）

2026-10-24。基于用户确认的紧凑监控 UX，原生实现于 TermViAI，沿用三套主题、侧栏、按钮悬浮、右侧抽屉和键盘焦点体系。此轮为本地试用，不增加正式 Beta 标签。

## 使用与交互

- 侧栏 Monitor → Add hosts，可搜索并多选已有 Hosts；已加入的主机不能重复添加。认证复用 Host 当前的 Password / SSH Key / Identity 设置。
- 总览为紧凑主机卡，显示状态、设备内存和 AICore 汇总。菜单支持暂停、恢复、重试及移除监控；移除监控不删除 Host。
- 进入主机后显示真实 NPU / Die 拓扑。整张 NPU 卡片只有一个悬浮预览和点击入口；内部 Die 行与指标不再分别弹层或跳转。
- 点击卡片打开右侧进程抽屉；All / Die 筛选只影响抽屉，显示 PID、用户、占用、命令及全部受影响的 Die。长内容可滚动。没有终端快捷入口。
- 主机、NPU / 当前 Die、单个进程可发起结束操作；确认页列出冻结的 PID 和影响范围。跨 Die 同一 PID 只发送一次请求。按钮默认中性，危险操作悬浮变红。
- 支持 2 / 5 / 10 秒采样间隔（一次采样结束后开始计时）。失败明确显示原因并提供重试；暂停保留最后一次数据及其时间。Tab / Shift+Tab、Enter / Space、Escape、滚轮可操作页面和抽屉。

## 数据与 SSH

`monitor.rs` 管理独立 SSH exec 会话和后台任务；不复用终端输入流，不往用户正在操作的终端写命令。`monitor_collect.py` 通过编码后的命令临时执行，不向远端安装 Agent 或写脚本文件。仅调用 `npu-smi info` 并读取 `/proc`，不会自行修改设备设置。

远端要求 Linux、可执行的 `python3` 与 `npu-smi`。解析表格中的 NPU/Chip 标识和列，不假设连续编号、固定卡数、固定 Die 数或容量。优先使用 HBM 列，设备未提供 HBM 列时读取 Memory-Usage；界面内存标签当前仍以 HBM 展示，主要面向 Ascend HBM 设备。N/A 保留未知，缺失进程区域不当作空闲。暂不支持 GPU、远端 Windows 或未识别的 npu-smi 表格变体。

未知 SSH 指纹不会自动接受，用户需先在 Hosts 打开该主机并确认指纹后重试。需要交互式 MFA 或未解锁密钥的认证会显示说明；当前监控不会弹出终端认证对话框。密码仍由现有凭据系统读取，不复制到监控文件。`monitor.json` 与 `hosts.json` 同目录，只保存 Host 元数据引用和采样间隔，采用临时文件替换。Host 名称或端点改变后需移除监控并重新添加。

## 进程操作

使用 SIGTERM 请求退出，不使用 kill -9 或按名称批量匹配。发送前再次读取 NPU 进程成员列表，并通过 boot_id + /proc starttime 与 pidfd 核对进程身份，避免 PID 重用。采样期间提交的操作等待该采样结束并再次验证；失败不会自动重放结束请求。

控制进程需要 Linux pidfd 和目标进程权限；优先使用 Python 自带接口，缺少绑定时通过 ctypes 调用 libc 包装，或在已核对的 Linux x86_64 / AArch64 LP64 ABI 上调用系统接口。能力检查打开采集器自身 pidfd 并使用信号 0（不会发送终止信号），不以 Python 版本或属性存在作为内核支持证明。无权限时保留查看能力。检测到容器标识或嵌套 PID 命名空间时禁用进程控制，避免把设备报告的宿主机 PID 当成容器 PID。容器环境中的 PID 映射不能保证正确，推荐直接监控宿主机。

返回信息区分已退出、已发送请求仍等待、权限错误和进程已变化。后续样本不再包含该 PID 时显示“不再由 NPU 报告”，不把释放 NPU 资源直接等同于进程退出。跨设备共享进程的确认页会列出所有受影响位置。

参考：[华为 npu-smi 进程表说明](https://www.hiascend.com/doc_center/source/en/CANNCommunityEdition/910/devaids/Profiling/atlasprofiling_16_0016.html)。

## 验证范围

Python 固定样本测试覆盖非连续拓扑、缺失进程表、未知 HBM、stat 中括号、过期 PID、非 NPU 进程、权限失败与容器控制限制；信号接口全部模拟，不连接真实主机或结束真实进程。

Rust 测试覆盖数据校验、PID 去重、命令编码、监控与 Host 数据分离、队列操作的身份变化与取消；原生绘制测试覆盖整卡单一命中以及 720×480、1024×768、1440×900 抽屉命中边界和遮罩阻止点击穿透。完整 Windows GUI 测试与 Release 编译记录见 UI_VALIDATION.md。

真实 SSH 认证、目标服务器 npu-smi 版本、长时间采样及原生鼠标/DPI 外观仍需试用验收；没有把固定样本或编译成功当成实机监控验证。

## 2026-10-24 首次采样失败修复

用户反馈所有主机显示 Unavailable，详情为 Remote collector failed。检查发现 monitor 在取得 exec 通道后立即 drop stdin，而当前 wezterm-ssh 的 SessionInner 在本地 stdin EOF 时会关闭整个通道（不是仅发送输入 EOF）。采集命令因此可能在返回结果前被关闭。现保留全部 exec 描述符直至输出和退出状态收集完成；不修改共享 SSH 库的终端/其他执行通道语义。

新增 Windows socketpair 回归验证等待输出与退出状态期间 stdin 必须仍打开，并覆盖保留远端 stderr、退出码与无 stderr 的错误说明。无首个样本时显示 Waiting for first sample，失败后显示 No successful sample，避免把远端命令失败误标为 Waiting for SSH。

用户提供 `/mnt/d/workspace/projects/npus-usage` 后，对照其 HostSession.exec 和 parser.js：参考实现保留 exec 流直至 close，并在 test-parser.js 中覆盖 25.5.1 的 Chip/Phy-Id 与 25.6.rc1 的单 Die/空 ID/NA Bus-Id 表格。旧采集器在这两个固定样本上均复现 Unsupported device table；已增加兼容，保留父 NPU 与 Chip/Die 的对应关系，不将 Phy-Id 当成父 NPU 编号。单 Die 进程行使用 NPU ID 并映射到 Die 0，忽略附加的容器 PID 列。原未知 HBM 不回退到 DDR 的保护保留。样例保存在 tests/fixtures，修改后 11 项 Python 测试通过。仅参考代码与测试数据，没有导入该项目的主机库或密码。

## 2026-10-24 对齐已确认 UX

本轮根据四张对照截图和 termviai-monitor.html 校正原生页面，保留现有应用侧栏宽度及英文文案。原稿采用 auto-fit/minmax，因此在 1024 与 1488 宽窗口下分别显示两列、四列，并非固定两列。

- Monitor / 主机标题 24 px、抽屉/空状态标题 17 px、卡片名 16 px、指标值 18 px、正文 12 px。新增缓存的独立 UI 字体尺寸/字重，跟随 DPI，不跟随终端字号；其他既有界面默认字体不变。
- 主机卡恢复图标、端点、状态/设备数量、暂停快照提示、错误说明与图标重试按钮；边框、圆角、指标标签/数值与进度条按稿排列。概览补充采集/暂停/异常计数，间隔改为 2/5/10 秒下拉选项。
- 详情面包屑为轻量文本链接；标题下为真实认证用户名/端点及分组，补分隔线和设备摘要。异常时头部切换重试，结束全部进程保持禁用；错误主体改为居中图标、标题、原因摘要、查看原因与重试入口。完整错误在独立抽屉展示。
- 设备数量/容量仅来源于真实或最近一次采样。首次失败时使用未知占位，不复制设计稿中的 8 NPU / 16 Die / 64 GB 示例数值。

布局测试覆盖概览与错误详情的三种窗口尺寸、字号层级、状态计数、错误页禁用操作和模态点击边界，另验证字体缓存、DPI 变化及终端字号独立性。布局 JSON 可由测试环境变量 TERMVIAI_MONITOR_LAYOUT_OUT 导出；离线 GDI 对照图仅用于坐标/文字排版审查，图标用名称占位，不能视为原生窗口截图或像素级验收。

## 2026-10-24 进程工作目录

进程详情新增 `Working directory`，读取远端 `/proc/<PID>/cwd` 符号链接，与 `pwdx PID` 对应，表示当前工作目录而非可执行文件所在目录。保留完整启动命令；路径按详情卡片宽度换行并参与滚动高度计算。路径含空格、Unicode 或内核返回的 `(deleted)` 后缀时原样保留（显示时仍清理控制字符）。

同一 PID 跨卡/Die 只采集一次元数据。工作目录读取失败显示 `Unavailable`，不影响其他采样信息或已验证的进程控制能力；采集前后进程身份变化时不发布该路径。模型允许旧采样/测试数据缺少 cwd 字段。容器的宿主 PID 映射限制仍适用，建议直接监控宿主机。

## 2026-10-24 NPU 悬浮预览卡片对齐

根据最新设计/实际截图，移除 NPU 卡片上的通用纯文字 tooltip，改为独立进程预览：330 px 卡片、9 px 圆角、主题边框与轻阴影；标题/进程数、逐进程分隔线、名称、PID/用户及右对齐显存，底部保留点击详情说明。悬浮延时 220 ms，与设计稿一致。预览没有额外点击区域，点击原卡仍打开详情；窗口底部自动向上显示，小窗口和进程较多时显示省略数量，完整列表仍在详情。

进程按 PID 去重，显存仅合计当前悬浮 NPU 的各 Die，不包含同 PID 在其他卡上的用量。空进程、进程信息不可用和暂停快照分别显示；错误页与模态详情不显示预览。不会用设计稿的示例数据替代真实样本。

保留原稿 auto-fit/minmax(280px) 的自适应列数，并限制列数不超过设备数量；两列/四列随可用宽度变化。NPU 卡片行高/留白及指标右对齐向稿中定义靠拢。居中/右对齐文字的测量宽度增加两物理像素余量，避免紧贴 glyph 裁切边界导致末字符（例如百分号）消失。

## 2026-10-24 进程详情文字与危险操作悬浮

进程详情正文从 12 px 调整为 13 px，进程名使用较重字重。监控显式 UI 字体启用 glyph 纹理原点的物理像素对齐，减少小字落在半像素位置时的纹理插值；保留字形尺寸、shaping advance、DPI 缩放和默认元素渲染入口，终端渲染不变。对齐使用屏幕坐标，而非居中的 GPU 坐标，覆盖奇数窗口尺寸。截图不能证明发糊的唯一原因，真实屏幕清晰度仍需验证。

结束单个/整卡/整机及最终确认操作改用 220 ms smoothstep 颜色过渡。常态不变，悬浮为 10% 红色染色背景、红色文字、45% 红色边框，按下为 18% 背景与 70% 边框；移入/移出中途反向保持连续。其他控件保留原 120 ms 动画。这里使用时间上的颜色渐入渐出，而非空间色带。

## 2026-10-24 详情滚动位置被背景重绘覆盖

用户报告长命令的进程抽屉出现滚动条却无法滚动。根因是背景 NPU 网格与抽屉共用 scroll/max_scroll：每帧先绘制网格，rows_range 按较短背景内容将抽屉位置截回 0，然后才绘制抽屉。现将背景 page_scroll 独立缓存，仅无抽屉时同步活动滚动位置；抽屉的滚动上限只由抽屉内容计算。关闭抽屉恢复背景页位置，采样更新继续保持有效位置。

抽屉滚动条新增 14 px 命中区域，支持滑块拖动和轨道点击定位。拖动期间拦截按下/移动/松开，避免误触进程操作；切换筛选/关闭等操作清理拖动状态。滚轮采用饱和加减并限制在有效范围内。

## 2026-10-24 滚动卡片越过标题栏与窗口操作修复

## 2026-10-26 Python pidfd 绑定兼容

216 的诊断为 Python 3.13.12 / Anaconda，os.pidfd_open 不存在但 signal.pidfd_send_signal 存在。旧版把绑定缺失统一提示成需要 Python 3.9+，因此即使能读取 PID、命令和工作目录，也禁用了所有进程控制。新版采样与终止共用 Pidfd 适配器；不回退到按数字 PID 调用 kill，保留 boot_id/starttime、NPU 成员和容器检查。

优先 Python 原生绑定，其次 libc 导出；只有已知 LP64 x86_64/AArch64 才使用 syscall 434/424。未知 ABI 在无导出时拒绝猜测；ENOSYS、EPERM/EACCES、命名空间限制和兼容库缺失分别给出原因。内核版本字符串不能替代能力探测（厂商内核可能回移功能）。

接口依据：[Python os.pidfd_open](https://docs.python.org/3.13/library/os.html#os.pidfd_open)、[Linux pidfd_open](https://www.man7.org/linux/man-pages/man2/pidfd_open.2.html)、[Linux syscall 表](https://github.com/torvalds/linux/blob/v5.10/arch/x86/entry/syscalls/syscall_64.tbl) 与 asm-generic/unistd.h。

# Host group navigation

Hosts uses a hierarchical group library, with the existing TermViAI palette, native vector icons and controls. The page heading provides Add Host and New Group; Add Host opens the new-host form directly at All Hosts and becomes a dropdown inside a specific group; search sits below it. Groups appear as folder cards above the Host cards. Host cards include the address, SSH username and the existing three-dot menu.

- All Hosts shows every saved Host and the top-level groups.
- Clicking a group opens it. The card has no redundant navigation arrow. Hovering its menu keeps the card highlighted, with a distinct surface on the menu icon; Host cards follow the same rule. Its independent three-dot menu offers New Host, Add Existing Hosts and Delete Group; the current breadcrumb level has the same menu. The Groups section shows only its immediate children. Hosts and the host count include every descendant, not just direct members.
- Breadcrumb labels use compact horizontal padding and clear 18 px gray separators. The All Hosts surface and hit area use the actual UI font advance plus equal 6 px padding, without moving the text or neighboring breadcrumbs. Blue breadcrumb ancestors navigate back to their level; the current group is plain text. Navigation clears the search and resets scrolling. Long/deep paths expose paging arrows so ancestors remain reachable within the window.
- Search is scoped to the current group and its descendants. It matches Host label, address, username and group path. Group cards are hidden while searching.
- New Group opens a centered compact card with Name and a read-only parent breadcrumb. Save creates a child of the captured current location and enters the new group; at All Hosts it creates a top-level group. Save and Cancel are neutral at rest; Save turns muted purple on hover. Escape/outside click cancels.
- Names are trimmed, limited to 60 characters, and cannot contain `/` or control characters. Names are unique within a parent (case-insensitive); different parents can have children with the same name. Empty groups persist across restarts.
- New Host, from the Add Host dropdown or a group menu, shows the destination in its header and pre-fills the existing Group input with the destination path. Opening, cancelling and saving keep the library at its original location; choosing New Host does not enter the target group. Editing that field can assign an existing path such as `PortForwarding / 218`, clear it to ungroup the Host, or create a new path. Duplicate Host retains its group.
- Empty groups show New Host and Add Existing Hosts. Blue breadcrumbs return to the parent. Large group and Host lists share the scrollable content region; the toolbar and breadcrumbs stay accessible.

- Add Existing Hosts is only available for a specific group, never All Hosts. The picker refuses an empty destination at both open and save, so it cannot accidentally ungroup selected Hosts. It opens a modal multi-select list of Hosts outside the destination's direct membership. Each row shows its current group and endpoint. Adding moves the selected Hosts, without duplicating them or changing authentication. The button stays inactive until a Host is selected. Wheel scrolling, arrow keys, Space/Enter selection and Tab to the footer are supported; Escape/outside click cancels.
- Delete Group opens a confirmation with neutral Cancel/Delete buttons and a complete rounded keyboard focus ring (Cancel initially); Delete becomes red on hover. Only the container is removed. Direct Hosts and immediate subgroups move to the parent, deeper group IDs remain stable, readable paths refresh, and all live connections, credentials and saved workspaces remain. Top-level direct Hosts become ungrouped. Promotion that would create a duplicate sibling name is refused without changing the file, with a conflict message.
- Bulk moves validate the whole captured selection against a fresh library before writing. A changed/deleted Host or deleted destination leaves the library unchanged. A New Host form cannot silently recreate a group deleted in another window.

## Storage and compatibility

`hosts.json` now includes `groups`, each with a stable `id`, `name` and `parent_id`. Hosts use `group_id`; the existing `group` string is retained as a readable path. Connection authentication, SSH sessions and saved terminal workspaces are separate from this grouping hierarchy.

Old Hosts with only a `group` string are projected into deterministic top-level groups during loading without changing those Host snapshots or writing the file. Existing labels containing `/` remain literal top-level names. The next library save persists the group definitions. Creating or editing a Host can adopt an explicit group ID. Exact legacy labels are resolved before interpreting a newly typed path.

Load/save rejects duplicate IDs, missing parents, parent cycles and explicit Host references to missing groups. Failed validation does not replace the file. New Group reloads the library before saving, so a concurrent sibling creation or removed parent cannot be silently overwritten. Host deletion keeps group definitions, including newly empty groups, and preserves the existing connection/credential behavior.

This implementation does not add SSH port forwarding; `PortForwarding` in the reviewed UX is a user-defined group name. Group rename and drag-to-move controls are not included.
